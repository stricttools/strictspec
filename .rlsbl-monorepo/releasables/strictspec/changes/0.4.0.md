## 0.4.0

Generated validators describe the constraint vocabulary without plan numbering, and the generated-code format moves to 2: regenerate committed validators with `strictspec gen` and raise the strictspec floor to this release.

<details>
<summary>Context</summary>

Generated validators carried the comment "evidence for the phase-2 constraint
vocabulary" on their evidence entry point, in all three targets. "Phase 2" was a
plan's numbering, not a name the code defines: strictspec's own validator calls
its two passes the structural pass and the constraint pass. The emitters now
write "evidence for the constraint vocabulary".

That comment is part of the emitted shape, and the conformance suite pins the
emitted shape against change unless the generated-code format moves. The format
moves to 2: the emitters write format 2, and every runtime reads formats 1
through 2. Format 1 stays readable because the change is a comment and nothing a
format-1 validator does differs. A consumer upgrading sees its committed
validators reported stale by `strictspec check`; regenerating them with
`strictspec gen` produces format-2 files, which need this release or later at
runtime, so the consumer raises its strictspec floor in the same change.

The validate command's help text also names its two modes by what they check
rather than by phase number.

</details>

### Breaking

- [go-strictspec, py-strictspec, ts-strictspec] **Generated validators no longer call the constraint vocabulary "phase-2", and the generated-code format moves to 2.** The comment on the evidence entry point (`ValidateBytesWithEvidence` in Go, `validate_bytes_with_evidence` in Python, `validateBytesWithEvidence` in TypeScript) now reads "evidence for the constraint vocabulary". Because the emitted code changed, `strictspec check` reports every committed validator as stale after upgrading. The remedy: regenerate each validator with `strictspec gen`, and raise your strictspec dependency floor to this release, since a format-2 validator refuses an older runtime at import or init with the format-mismatch error. Validators generated at format 1 keep working against this runtime.

### Fixes

- [go-strictspec, py-strictspec, ts-strictspec] **`strictspec validate --help` describes its modes by what they check.** `--structural-only` now reads "Run the structural checks only" and `--with-domain-checks` reads "Also run the constraint vocabulary checks", instead of numbering them phase-1 and phase-2.
